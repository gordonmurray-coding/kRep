kRep

What Toccata is actually for.

kRep is portable pseudonymous reputation, minted as a side effect of settlement. It is also a nine-branch native covenant state machine driven end to end against consensus — and a report on what building one taught us about Kaspa.

Why Kaspa

This is not a chain-agnostic project.

The load-bearing mechanism is the unilateral default: a record of failure that the failing party never signs. Reputation systems collapse without it, because a defaulter will not co-sign their own default and no amount of protocol design gets a signature out of someone who has already left.

A covenant solves it. It cannot produce a signature either, but it can force bytes into the payload of the transaction that takes the bond. So a covenant-witnessed attestation carries no signatures at all, and its authority is the on-chain fact that the slash branch executed. That requires native introspection over outputs, payloads and time — which on Kaspa arrived with Toccata (KIP-16/17/20/21), live on mainnet since DAA 474,165,565.

Covenants
OpTxOutputAmount, OpTxOutputSpk, OpTxPayloadSubstr and friends let the escrow enforce its own state machine. State is threaded by having the spender supply the previous transaction’s bytes and re-deriving its id in script.
Payload space
A settlement can carry the attestation ids it mints. Reputation therefore costs no extra transaction — it is a side effect of getting paid.
10 blocks/sec
Deadlines and dispute windows measured in DAA score are fine-grained enough to be practical rather than ceremonial.
Fees
The mainnet settlement that minted two reputations cost 169,900 sompi. Per-trade anchoring is affordable, which is the whole Sybil-resistance argument: forging a history means buying it, deal by deal.

What is running

A nine-branch covenant, exercised against consensus.

Claim, ship, settle, auto-release, dispute, resolve-to-maker, resolve-to-buyer, slash and refund — every branch driven on testnet-10 against real consensus rather than a local VM. The attestation and anchoring loop has additionally run on mainnet, where the predicted transaction id matched the broadcast one exactly.

Field notes

Things only the network could teach.

Offered because the next person building a covenant on Kaspa will hit these, and each one cost a live run to find.

  • Script-unit budget grows with the whole script, not the branch taken. An input commits a budget in sigop units, one unit buying 100,000 script units. A covenant’s dispatcher scans past every earlier arm to reach the one being spent, so the last arms of the arbitrated covenant measured ~205,000 units. Claim and ship succeeded on a budget that resolution was rejected for. Arm ordering is a cost decision, not a style one.
  • Lock time must be strictly in the past. Equal to the current DAA score counts as not passed, so a transaction submitted the instant its deadline arrives is rejected as not finalized — which reads like a signing or covenant fault and is neither. Every timed branch needs to either back its lock time off or tell the user how long remains.
  • kaspad has no transaction index. No getTransaction(txid). An anchor therefore cannot name the settlement that commits it — that would be circular anyway, since the id is inside the payload that determines the txid. Anchors instead name the outpoint the settlement spends, and verification searches forward for whatever consumed it.
  • Every covenant branch is a different script, so a naive design is a different address. Which breaks state continuity outright. The branches have to sit behind one dispatcher so the escrow keeps a single P2SH address across its whole lifecycle.
  • Bulk reads beat per-block reads by an order of magnitude. Fetching blocks individually cost about four minutes per chain batch; get_blocks returning a whole mergeset brought the same window to twenty-three seconds. On a 10 BPS chain that is the difference between “anyone can maintain this” being true and being a slogan.
  • Scan payloads at aligned offsets. Indexing every position a 32-byte id could occupy makes a payload of length L cost L−31 entries instead of L/32. Measured on testnet-10 that was 48,057 index entries where 1,611 would do — and the excess was driven by other protocols’ payload traffic, not ours.

What it needs

Three things, none of them code.

  • A second party.Every trade so far has been one person holding both sides. Counterparty diversity has therefore never been a real signal, and a dispute has never had two people who actually disagreed. One other trader would find more than another month of building.
  • Review of the covenant.Nine branches enforcing custody of real funds, written by one author. It is exercised against consensus, which is not the same as being audited by someone trying to break it.
  • An archival node.Kaspa prunes, so a record becomes unreadable without becoming untrue. Long histories need someone retaining more than the pruning window; the software says “cannot confirm” rather than guessing, but that is a limit, not a solution.

What is proven, and what is not

A reputation system asking to be believed should be specific about its own evidence.

✓

Mainnet settlement carrying two attestation ids. 330861aa…, both chains verifying, one trade scored on each side, and the predicted txid matching the broadcast one exactly.

✓

The unilateral default works on-chain. A maker was slashed on testnet-10 and the covenant wrote the failure with no signature from them. The same chain with that entry omitted — which still verifies structurally — was refused, so a defaulter cannot launder their record by sending a shorter file.

✓

The zero-knowledge proof is real. Barretenberg UltraHonk, against roots rebuilt from a full pruning window. A proof built on a different accumulator fails, and so does a proof of a circuit that asserts nothing.

—

Escrow has run only on testnet-10. Mainnet has carried the attestation and anchoring loop, not the covenant. Moving custody to mainnet is a decision that should follow review, not precede it.

—

Every trade was self-dealt. The mechanism works; the market does not exist yet. The marketplace currently has three listings and they all belong to the author.
